# داشبورد مالی و عملیاتی لجستیک

یک برنامهٔ محلی و **On-Premise** با Python، Streamlit و SQLite برای ثبت داده‌های ماهانهٔ واردات و صادرات و ساخت گزارش عملکرد، بودجه، درآمد، هزینه و سود. برنامه برای داده‌های مالی به سرویس ابری یا API خارجی متصل نمی‌شود؛ آمار استفادهٔ Streamlit نیز غیرفعال است.

## ساختار پروژه

```text
.
├── app.py                         # نقطهٔ ورود Streamlit
├── requirements.txt               # وابستگی‌های پایتون
├── .streamlit/config.toml          # تنظیمات محلی Streamlit و ظاهر پایه
├── dashboard_app/
│   ├── config.py                   # مسیرها، دوره‌ها، گزینه‌های ثابت
│   ├── database.py                 # schema، اتصال SQLite و audit log
│   ├── seed.py                     # بارگذاری یک‌بارهٔ داده‌های نمونه
│   ├── repository.py               # عملیات خواندن/نوشتن داده و خدمات
│   ├── auth.py                     # ورود محلی، نقش‌ها و هش گذرواژه
│   ├── calculations.py             # منطق KPI و گزارش
│   └── views/
│       ├── analytics.py             # داشبورد و گزارش نهایی
│       ├── data.py                  # ثبت، جست‌وجو و مدیریت خدمات
│       ├── admin.py                 # کاربران، سابقه و پشتیبان‌گیری
│       └── common.py                # ظاهر، قالب‌بندی و دریافت خروجی
├── data/demo_records.csv           # داده‌های ساختگی اولیه، شامل هزینهٔ ساختگی
├── tests/test_calculations.py      # آزمون فرمول‌های گزارش
└── instance/                       # پایگاه دادهٔ زنده؛ خودکار ساخته می‌شود و Git آن را نادیده می‌گیرد
```

## اجرا روی رایانهٔ میزبان

Python 3.10 یا جدیدتر لازم است.

### Windows (PowerShell)

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

### Linux یا macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

در اجرای نخست، صفحهٔ ساخت حساب مدیر باز می‌شود. **این راه‌اندازی را ابتدا روی خود رایانهٔ میزبان انجام دهید**؛ سپس برنامه را برای شبکه در دسترس بگذارید. گذرواژهٔ پیش‌فرض یا حساب کاربری hard-coded وجود ندارد.

## دسترسی از شبکهٔ داخلی

برنامه را فقط روی یک رایانهٔ مورداعتماد در شبکه اجرا کنید:

```bash
streamlit run app.py --server.address 0.0.0.0 --server.port 8501
```

کاربران مجاز در مرورگر به `http://<IP-داخلی-میزبان>:8501` وصل می‌شوند. دسترسی پورت 8501 را در فایروال فقط برای subnet داخلی شرکت مجاز کنید؛ پورت را روی روتر به اینترنت forward نکنید. برای استقرار سازمانی، TLS را با reverse proxy داخلی فعال کنید.

پایگاه دادهٔ SQLite روی **دیسک محلی همان میزبان** ذخیره می‌شود؛ آن را روی NAS یا پوشهٔ اشتراکی SMB قرار ندهید. تنظیم مسیر:

```bash
# Linux/macOS
export DASHBOARD_DB_PATH=/srv/secure-finance/finance_dashboard.sqlite3

# Windows PowerShell
$env:DASHBOARD_DB_PATH = "D:\SecureFinance\finance_dashboard.sqlite3"
```

اگر `DASHBOARD_DB_PATH` تنظیم نشود، فایل در `instance/finance_dashboard.sqlite3` ساخته می‌شود. پوشه باید برای حساب سیستم‌عاملی اجرای Streamlit قابل‌نوشتن و برای کاربران دیگر محدود باشد.

## نقش‌ها و امنیت

- **مدیر:** ثبت و اصلاح داده، حذف رکورد، مدیریت خدمات و کاربران، دریافت پشتیبان و مشاهدهٔ سابقهٔ تغییرات.
- **ثبت‌کننده:** ثبت/به‌روزرسانی داده و مشاهدهٔ گزارش‌ها.
- **فقط‌خواندنی:** مشاهدهٔ داشبورد و خروجی گزارش.
- حداکثر ۱۰ حساب فعال پذیرفته می‌شود.
- گذرواژه‌ها با PBKDF2-HMAC-SHA256 و salt تصادفی ذخیره می‌شوند؛ مقدار خام گذرواژه در پایگاه داده یا log ثبت نمی‌شود.
- پس از ۵ ورود ناموفق، حساب برای ۱۵ دقیقه موقتاً قفل می‌شود. نشست پس از ۳۰ دقیقهٔ بی‌فعالیتی منقضی می‌شود.
- تغییر داده، ورود/خروج، تغییر حساب و حذف داده در audit log ثبت می‌شود.
- مدیر می‌تواند از صفحهٔ «حساب و امنیت» نسخهٔ پشتیبان سازگار از SQLite دریافت کند. فایل پشتیبان هم شامل داده‌های مالی و هم هش حساب‌هاست؛ آن را در محل امن و محدود نگه دارید. SQLite به‌تنهایی رمزنگاری در حالت سکون انجام نمی‌دهد؛ رمزنگاری دیسک میزبان (مانند BitLocker یا LUKS) و محدودکردن مجوز پوشه را فعال کنید.
- `.gitignore` پایگاه داده و فایل‌های WAL را از Git خارج می‌کند. فایل `data/demo_records.csv` فقط دادهٔ ساختگی برای نمایش و آزمون است.

SQLite برای استفادهٔ شبکه‌ای با حداکثر حدود ۱۰ کاربر و حجم ثبت معمول مناسب است، به‌شرط آنکه همهٔ کاربران به یک نمونهٔ Streamlit و یک فایل پایگاه داده روی میزبان وصل شوند. نوشتن‌های هم‌زمان در SQLite پشت‌سرهم انجام می‌شوند؛ اگر تعداد نوشتن هم‌زمان یا حجم داده به‌طور محسوسی بالا رفت، PostgreSQL محلی گزینهٔ مناسب‌تری است.

## ساختار و ورود داده

شیت مرجع `Database_Ready` مبناست: سال شمسی، ماه، دوره، بخش، شرح خدمت، واحد سنجش، مقدار، درآمد و نوع رکورد. ساختار پایگاه داده نرمال‌سازی شده است: نام بخش/خدمت/واحد در جدول خدمات نگهداری می‌شود و جدول رکوردها با کلید خدمت به آن وصل است. برای گزارش، داده‌ها به شکل همان ساختار مرجع نمایش داده می‌شوند. بخش‌های قابل انتخاب **واردات** و **صادرات** هستند؛ بخش حمل‌ونقل در این نسخه وارد نشده است.

هر رکورد یک خدمت در یک ماه و یک نوع داده است. ترکیب سال، ماه، خدمت و نوع رکورد یکتا است؛ ثبت دوبارهٔ همان ترکیب، رکورد قبلی را به‌روزرسانی می‌کند. گزینه‌های نوع رکورد:

- عملکرد دورهٔ جاری
- بودجهٔ مصوب دوره
- عملکرد دورهٔ مشابه سال قبل

سال واردشده سال واقعی داده است. برای مثال، برای مقایسهٔ عملکرد گزارش ۱۴۰۳ با سال قبل، دادهٔ مقایسه‌ای با سال ۱۴۰۲ ثبت می‌شود. دورهٔ سه‌ماهه از ماه به‌طور خودکار به‌دست می‌آید. فهرست خدمات و واحدها از نمونه اولیه ساخته می‌شود و مدیر می‌تواند آن را تغییر دهد.

## فرمول‌های گزارش

- سود = درآمد − هزینه؛ این مقدار برای عملکرد جاری، بودجه و دورهٔ مشابه سال قبل محاسبه می‌شود.
- تحقق بودجهٔ مقدار/درآمد/سود = مقدار عملکرد ÷ مقدار بودجه × ۱۰۰.
- انحراف نسبت به سال قبل = عملکرد جاری − عملکرد دورهٔ مشابه سال قبل.
- رشد سالانه = (عملکرد جاری − عملکرد سال قبل) ÷ قدرمطلق عملکرد سال قبل × ۱۰۰.
- انحراف هزینه از بودجه = هزینهٔ واقعی − بودجهٔ هزینه.
- در مخرج صفر، درصد نمایش داده نمی‌شود تا تقسیم بر صفر رخ ندهد.
- مقدارهای عملیاتی در گزارش جمع می‌شوند؛ برای خدمت «میانگین مدت ماندگاری کالا» میانگین ماهانه استفاده می‌شود. درآمد و هزینه همیشه جمع دوره هستند.

## داده‌های نمونه

`data/demo_records.csv` شامل ردیف‌های ساختگی واردات و صادرات شیت پایگاه داده است. فایل اصلی هزینه نداشت؛ بنابراین هزینهٔ نمونه به‌صورت **ساختگی و قطعی** از روی درآمد و با نسبت‌های تقریبی متغیر ساخته شده تا محاسبهٔ سود در داشبورد قابل مشاهده باشد. در درآمد صفر، هزینهٔ نمونه نیز صفر است. این مقادیر برای تصمیم‌گیری مالی واقعی نیستند.

داده‌های نمونه در نخستین راه‌اندازی فقط یک‌بار وارد می‌شوند. مدیر می‌تواند بعداً از صفحهٔ جست‌وجو آن‌ها را حذف کند. ویرایش هر ردیف نمونه، همان ردیف را از حالت نمونه خارج می‌کند. اگر برنامه را روی دادهٔ واقعی راه‌اندازی می‌کنید، پس از آزمون نمونه‌ها را حذف و پشتیبان امن تهیه کنید.
